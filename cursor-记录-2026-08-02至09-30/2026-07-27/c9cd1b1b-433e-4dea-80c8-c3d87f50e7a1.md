## 二、立项理由 1：动作是美术成本里「最大、最碎、最可 AI 化」的单池

### 成本结构（附件 + 访谈交叉验证）

```
整个研发预算
├── 美术 45%（基准，常见 35–55%）
│   ├── 角色模型 ~1/3（研发期）
│   ├── 场景模型 ~1/3
│   └── 动作/动画 占美术 25–40%（3D 动作类）
├── 工程 25%
├── 策划 13%
└── 其他 …
```

**山海量级（5–6 亿研发）粗算：**

- 美术约 **2.25–3 亿**
- 动作约 **5600 万–1.2 亿**（按 25–40% 计）
- 运营期动作再占 **~1/4**，且运营总成本约 **研发的一半** → 动作是**持续烧钱点**，不是一次性

### 外包视角（更贴近「能省多少钱」）

- 动作外包 ≈ **1/3**
- 3D 角色模型 ≈ **1/4**
- 场景 + 动作 ≈ **各 1/3 量级**

动作是外包里**占比最高、最碎、批量最好**的模块——行业里已有百人动作公司 + 动作库，说明：**动作是标准化程度最高、也最该被 AI 放大的环节**。

## 三、立项理由 2：动作是「资产→应用」链路上唯一还没被 AI 打穿的枢纽

3D 制作主链路：

```
原画 → 模型 → 绑定/蒙皮 → 动作 → 特效/镜头 → 进引擎/编辑器 → 策划调取
         ↑ Tripo          ↑ GoSkin      ↑ ???              ↑ 表格/人工沟通
       （已 AI 化）      （已 AI 化）   （仍是人力）        （未系统化）
```

**一个角色 = 一个模型 + 上千条动作**（山海主角）。模型是一次性，动作是**持续、海量、按体型/外装/交互反复叠加**的。

访谈里的痛点：

- 策划要在表格里找 NPC 动作，或问美术
- 交互动作（如拥抱）按体型（女孩/成女/成男）各做一套
- 通用动作（走/待机/攻击）靠体型共用，但**特殊/表演型动作**纯手K，工量少、单价极高

**打穿含义：** 不是「生成一条动作」，而是：

> **文生/约束生 → 自动重定向到 Biped/引擎骨架 → 写入动作库 → 策划按标签/场景/NPC 直接调取**

MotionForge 的 PRD 正是在补这一环：`SOMA77 → Biped 重定向 → 写回时间线 → 导出动作库`。

## 六、立项理由 5：动作复用率最高，AI 放大的是「已有优势」

访谈强调：

- **动作复用率 > 模型复用率**
- 所有 NPC 都要走/待机；怪物都要攻击
- 外包公司靠**动作库 + 批量**赚钱
- 体型共用（山海 3 个体型）进一步放大复用

AI 动作工具的价值不是替代动捕库，而是：

1. **库里没有的**：文生快速补货  
2. **库里有但不贴合的**：Pose/路径约束微调  
3. **新体型/新外装**：自动重定向，减蒙皮后补动作成本  
4. **策划试想法**：分钟级验证，减少美术无效沟通  

这和「闲鱼提升资产复用率」同逻辑，但**动作是复用率最高的资产类型**，AI 杠杆最大。

| **场景模型** | ≈ 1/3 | 与动作量级接近 |
| 其他（UI、特效等） | 剩余 | — |

**修正：** 不是「场景 + 动作 = 动作 1/3」，而是 **场景 ≈ 1/3、动作 ≈ 1/3**，两者都是外包大头。

#### 山海量级粗算（5–6 亿研发）

- 美术约 **2.25–3 亿**（45% 基准）
- 动作相关（占美术 25–40% + 运营持续投入）→ 研发期 **5600 万–1.2 亿**
- 运营期动作再占 **~1/4**，且运营总成本 ≈ 研发一半 → **持续烧钱**

#### 蒙皮只是动作链上一环，已省 300w；整条动作链是近亿级

| 环节 | 传统 | AI | 节省 |
|------|------|-----|------|
| **蒙皮/重置骨骼**（动作链一环） | ~400w | ~100w | **300w** |
| **动作初版生成**（整条链） | 手K/外包/动捕 | Motion Gen + 重定向 | **按项目近亿级** |

蒙皮只证明了一件事：**动作链上任意一环 AI 化，ROI 都极高。** 文生动作直接打在「制作」主环节，杠杆比蒙皮更大；且动作做完可**跨项目复用**，模型/场景做不到。

### 三、动作量级：主角上千条、NPC 按体型共用，量极大

#### 公开资料（与访谈「主角上千动作」一致）

| 来源 | 主角/玩家 | NPC/项目总量 |
|------|----------|-------------|
| **山海（访谈）** | **1000+ 条** | 200–300 NPC × 体型共用 |
| MoCap Online（MMO 指南） | 200–400 条/角色 | 全项目 **500–2000+** 条；NPC 原型 **15–30 条/类** |
| WoW（AnimationData） | 引擎层 **452+** 动画 ID（0–451），随版本扩展至 **500+** | 多种族/职业/技能叠加后项目级 **数千条** |
| 塞尔达 OOT（Link） | **572 条** | — |
| 尼尔 2B | **100+ 条** | — |
| 早期 MMO（EverQuest） | <20 条/种族 | 现代 Lost Ark / FF XIV：**每职业数百条** |

#### 按复杂度分层（行业共识 + 山海访谈）

**主角 / 可玩角色（动作类 MMO）**

- 基础 locomotion：走/跑/跳/落地/转向等，**8–16+ 条**（仅移动）
- 战斗/技能/交互/表演/过场：**数百–1000+ 条**
- 山海主角 **1000+** → 处于 **3A 动作 MMO 上限区间**

**NPC（按体型共用，山海 3 个体型）**

- 最低配：idle 2–3 变体 + 巡逻 + 警觉 + 交互 + 反应 ≈ **15–30 条/原型**
- 山海 200–300 NPC，普通 20 人天占一半以上 → 大量「够用但不精致」的通用动作
- 交互动作（如拥抱）按体型各做一套 → **+1 交互 = ×3 工作量**

**结论：** 动作是 **「一个模型 + 海量动作」** 的结构；模型一次性，动作持续、按体型/NPC/版本叠加——**AI 省的是重复劳动，不是单条精品。**

### 四、「打穿」定义：资产管理 + MotionForge 全链（美术自用）

**打穿 ≠ 给程序/策划用工具。** 核心是 **美术同学自己**：生成 → 入库 → 检索 → 写回 DCC → 精修 → 再复用。

```
│  → 写回动画层 → 手K精修 → 导出 .bip/.xaf → 回 Layer 1 入库  │
└─────────────────────────────────────────────────────────┘
```

#### MotionForge PRD 链条（美术工作流）

```
点选 Biped（采集朝向/骨骼/身高）
  → 中文描述 + 时长（或模板库）
  → 可选：Pose 约束 / 路径约束 / 多段序列 / Seed 锁定
  → Motion Gen 推理（Kimodo 等）
  → 多样本抽卡对比（n=1~4）
  → 选中样本 → SOMA77 → Biped 重定向
  → 写入独立动画层（可撤销）
  → 时间线继续手 K 精修
  → 导出 .bip / .xaf（命名含 prompt 摘要 + seed）
  → 进入动作资产库（标签、版本、复用）
```

**美术的真实痛点（访谈）：**

- 以前靠表格找动作，或问同事「这个 NPC 有没有某某动作」
- 不是程序问题，是 **资产散、检索难、沟通成本高**
- AI 辅助 = **少沟通 + 快出初版 + 统一入库**

### 六、复用理由：动作是 3D 里复用率最高、跨项目价值最大的资产

| 资产类型 | 跨项目复用 | 跨品类复用 | 说明 |
|---------|-----------|-----------|------|
| **动作** | ✅ 强 | ✅ 甚至小游戏能用 | 走路/攻击/待机通用；体型 retarget 后可复用 |
| **3D 角色模型** | ❌ 弱 | ❌ 风格/引擎/规格绑定 | 山海次世代 ≠ 剑三手绘 |
| **场景模型** | ❌ 弱 | ❌ 项目世界观绑定 | 几乎不可迁移 |

访谈印证：

- 动作外包公司 **百人团队 + 自有动作库**，批量最好
- 所有 NPC 都要走/待机，怪物都要攻击 → **通用动作需求高度同质**
- 山海按 **3 个体型** 共用 → retarget 放大复用

**商业含义：** 一次 AI 动作投入 → **当前项目省钱 + 动作库跨项目/跨版本/甚至小游戏复用**；模型/场景 AI 没有这层复利。
