## 3. Codex

如果你说的是“游戏角色 3D 骨骼动作生成”，目前开源方案已经不少，但多数仍属于“生成动作草稿 + 动画师清理”，还不能完全替代 MotionBuilder/Maya/Blender 的动作制作。

### 值得关注的方案

| 方案 | 主要能力 | 游戏制作适用性 | 注意点 |
|---|---|---:|---|
| [HY-Motion 1.0](https://github.com/Tencent-Hunyuan/HY-Motion-1.0) | 文本生成 3D 人体动作 | ★★★★☆ | 当前开源方案里质量和指令理解较强；标准版约需 26GB 显存，Lite 约 24GB。暂不支持动物、多人、无缝循环和原地动作 |
| [MoMask](https://github.com/EricGuo5513/momask-codes) | 文本生成、局部重绘、动作补全 | ★★★★★ | 能直接导出 BVH，并提供 Blender/Mixamo 骨骼重定向流程，最适合快速接游戏管线；自带简单脚部 IK，但仍可能失败 |
| [MDM](https://github.com/GuyTevet/motion-diffusion-model) | 文本/动作类别生成、上下身编辑、动作补间 | ★★★★☆ | 经典成熟基线，MIT 代码许可，资料丰富，适合二次开发和训练自己的风格模型 |
| [MotionGPT](https://github.com/OpenMotionLab/MotionGPT) | 文本生成、动作描述、预测、补间 | ★★★☆☆ | 功能全面，输出 22 关节序列；更偏研究平台，接入 Unity/Unreal 前需要自己补转换和重定向 |
| [MotionLab](https://github.com/Diouo/MotionLab) | 动作生成、风格迁移、局部编辑、补全 | ★★★★☆ | 适合“已有动作改风格、改局部、修中间段”，比单纯文本生成更贴近动画师工作流 |
| [DART](https://github.com/zkf1997/DART) | 路径约束、场景交互、实时连续动作 | ★★★★☆ | 能处理走到目标点、坐椅子、下楼等场景约束；控制策略可达 300+ FPS，但部署和训练复杂 |
| [GVHMR](https://github.com/zju3dv/GVHMR) | 单目视频提取世界坐标人体动作 | ★★★★☆ | 严格说是 AI 动捕，不是文本生成；适合手机拍参考动作，再重定向给游戏角色 |

### 我会怎么选

- 想最快做出可导入 Blender/Unity/Unreal 的动作：**MoMask**
- 有 24GB 以上显存，追求文本生成质量：**HY-Motion**
- 想搭建自己的动作生成系统或训练模型：**MDM**
- 想修改已有动作、做补间或风格变化：**MotionLab**
- 想让 NPC 根据路径、目标点和场景连续运动：**DART**
- 有演员/参考视频，追求动作可控性：**GVHMR**

### 推荐的游戏生产管线

```text
文本或参考视频
→ HY-Motion / MoMask / GVHMR
→ SMPL/HumanML3D 骨架动作
→ 脚部锁定、Root Motion、接触和循环清理
→ Blender/Maya 骨骼重定向
→ FBX
→ Unity Mecanim / Unreal IK Retargeter
```

实际落地时最容易踩坑的是：

- 生成结果通常不是游戏标准骨架，需要重定向。
- 脚滑、穿地、手碰不到物体仍很常见。
- 攻击动作需要武器约束、打击帧和 Root Motion，通常要人工二修。
- 动物、四足、怪物和非标准骨架的成熟开源模型明显少于人体模型。
- “代码开源”不等于训练数据和模型权重可直接商用。HumanML3D、AMASS、SMPL/SMPL-X 以及各项目权重都有独立许可，商业项目必须逐项检查。

如果是准备做实际项目，我建议第一轮用 **MoMask → BVH → Blender 重定向 → FBX** 验证整条管线；确认质量上限后，再评估是否值得部署 HY-Motion 或训练自有模型。
