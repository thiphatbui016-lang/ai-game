## 1. AI 时代怎么定义好的原画

**“好看”已经从终点变成入场券。**

好的原画应定义为：

> 在世界观、玩法、角色身份、镜头、性能和生产周期约束下，给出有辨识度、可拆解、可延展、可落地的视觉解决方案。

建议从六个方面评价：

1. **辨识度**：不是“AI 平均意义上的漂亮”。
2. **叙事和玩法功能**：能表达身份、阵营、职业、危险性和交互功能。
3. **生产可落地**：3D、材质、绑定、动画和特效知道怎么做。
4. **系统一致性**：符合项目的比例、形状语言、色彩和材质体系。
5. **延展性**：能继续生产皮肤、阵营、等级、损坏态等变体。
6. **成本与风险**：符合平台预算、周期和版权要求。

所以以后原画验收不能只问“好不好看”，还要问：

- 哪些是明确设计，哪些只是 AI 随机装饰；
- 三视图和结构是否一致；
- 下游工种是否可以无歧义执行；
- 能否稳定扩展同一角色和同一阵营；
- 输入参考、模型、人工修改和版权能否追溯。

## 2. “把单元文件放进引擎”是什么意思

合理理解不是把所有 PSD、Maya、Houdini 工作文件塞进 UE，而是：

> 引擎里保存可以独立版本、替换、组合、参数化和批处理的最小生产单元，而不是只保存一个合并烘焙后的最终结果。

单元可以是：

- 模块化墙体、门窗、道路、岩石、植被；
- Mesh、Material Instance、Material Function；
- Niagara 模块；
- Blueprint Actor/Component；
- PCG Graph、HDA；
- Level Instance、Data Layer；
- Control Rig、IK Rig；
- Data Asset、导入清单、验证规则。

推荐边界：

- **DCC 源文件**放 P4、DAM 或对象存储；
- **引擎生产单元**放 UE 工程；
- **Import Manifest**记录源文件、引擎对象、版本、导入参数、任务和版权关系；
- 最终地图和角色由这些单元组合产生。

UE 官方已经提供 Interchange 导入管线、数据验证、Editor Utility/Python 等基础能力；World Partition 与 One File Per Actor 也有利于降低多人修改同一大地图文件的冲突。citeturn2search0turn2search3turn1search0turn1search5

## 3. 生产平台具体怎么桥接 DCC 和引擎

推荐链路：

```text
任务平台
→ AI Run/候选输出
→ 人工选择
→ DCC Handoff
→ DCC 精修与发布母版
→ Asset Version
→ Ingest Gate
→ UE Staging 隔离导入
→ 自动验证与预览
→ 人工审核
→ 正式资产晋级
→ 结果回写任务平台
```

核心组件：

- **AI Gateway**：记录模型、工作流、种子、成本和结果；
- **Asset Registry**：资产ID、版本、依赖、负责人和状态；
- **Production Lineage**：输入→生成→选择→人工修改→审核→交付；
- **DCC Adapter**：Photoshop、Maya、Max、Blender、Houdini 等插件；
- **UE Adapter**：导入、重导入、验证、截图、Diff、提交和回滚；
- **Ingest Gate**：规范、质量、性能、来源、版权和重复性检查；
- **权限系统**：控制谁能对哪张地图、哪个区域、哪类资产执行什么操作。

你当前目录中的 `ai_asset_control_plane_mvp` 已经覆盖了：

```text
任务 → AI Run → Photoshop Handoff
→ Asset Version → Review → Ingest Gate → Production Lineage
```

下一步主要是补充**真实 DCC 插件和 UE Adapter**。

### MCP 的位置

MCP 可以负责“理解自然语言、发现工具、组织任务”，但不建议把它直接作为生产资产写入协议。

生产执行层仍要使用：

- 版本化 API；
- 结构化命令；
- 幂等键；
- 短期权限令牌；
- 作业和事务 ID；
- 可重试、可审计、可回滚的状态机。

即：**MCP 负责上层编排，受控插件负责真正修改资产。**

## 5. 商业软件开放度和 MCP 情况

截至 **2026年9月6日**，应把“官方自动化能力”和“MCP 项目”分开看：

- Photoshop：官方有 UXP/API；
- Substance：有 Python、插件和自动化接口；
- Maya：Python、MEL、C++ API、批处理能力较强；
- 3ds Max：MAXScript、Python、C++ SDK；
- Blender：完整 Python API、后台模式，开放度最高之一；
- Houdini：HOM、HAPI、Houdini Engine，特别适合程序化和批处理；
- ZBrush：以 ZScript/插件为主，自动化边界相对窄；
- Marvelous Designer：具备 Python/REST 等接口，但要按具体版本做 POC；
- UE：C++、Python、Editor Utility、Commandlet、Interchange、Data Validation。citeturn3search0turn4search2turn5search0turn5search5turn8search0turn8search5turn8search7turn11search0turn11search6

目前大量 DCC MCP 属于**社区项目或概念验证**，不能因为“GitHub 上有一个项目”就判断达到生产要求。例如 Blender、Maya、Houdini 等已有社区 MCP；Autodesk 官方公开的 Product Help MCP 主要面向帮助文档查询，并不等同于官方 Maya/Max 编辑控制协议。citeturn9search0turn7search0turn10search0turn5search8

### 正版还是破解

生产平台必须只支持正版和授权明确的软件：

- 不接入破解软件；
- 不绕过许可证、DRM或登录；
- 记录版本、Seat、用户、机器和授权范围；
- 社区 MCP 的开源许可，不代表被控制的商业软件可以无授权使用；
- 破解环境无法保证安全、升级、插件稳定、审计和商业合规。

## 6. 几十人对整张 UE 地图批处理怎么办

不能允许一句自然语言直接改整张地图。

正确流程：

```text
自然语言需求
→ 结构化批处理计划
→ Dry Run
→ 影响对象清单
→ 权限和冲突检查
→ 创建快照/Changelist
→ 分区执行
→ 自动验证
→ 前后截图和数值 Diff
→ 人工审核
→ 提交或回滚
```

权限至少要细到：

- 项目；
- 地图；
- World Partition 区域；
- Data Layer；
- 资产目录和类型；
- 创建、修改、删除、重导入、移动、提交、发布等操作；
- 单次最大影响数量；
- 任务有效时间；
- 审核人。

要特别注意：UE Multi-User Editing 主要解决实时协作与同步，它要求参与者具有一致的工程和源代码控制基线，**不能替代细粒度权限、Changelist、审核和正式发布制度**。citeturn1search2turn1search3

## 7. 什么叫稳定性强，什么叫“没降智”

### 稳定性强

不是“这次跑通了”，而是：

- 不越权修改；
- 可以安全重试；
- 重试不会重复创建资产；
- 每一步都能追溯；
- 失败可以完整回滚；
- 软件或模型升级后能跑回归测试；
- 单个坏资产不会拖垮整批任务；
- 长时间运行不积累状态污染。

### 没降智

建议定义为：

> 在固定的岗位 Golden Set、固定输入、权限和验收规则下，新版本任务完成率、人工接受率、质量分和风险指标没有显著低于批准基线。

建议首批指标：

- 越权写入：**0**
- 审计链完整率：**100%**
- 可回滚比例：**100%**
- 关键任务回归通过率：**100%**
- 普通批处理成功率：**≥99%**
- 首轮人工接受率：不低于基线
- 人工修改时间：不高于基线
- Cost per Accepted Asset：不高于基线的110%

这些是建议的试运行门槛，不是行业统一标准。

## 8. 1K、2K、4K 是否影响成本

影响非常明显。边长翻倍，像素数量是4倍：

| 分辨率 | 像素数 | RGBA8未压缩 | BC7/BC3类约值 |
|---|---:|---:|---:|
| 1K | 约105万 | 4 MiB | 1 MiB |
| 2K | 约419万 | 16 MiB | 4 MiB |
| 4K | 约1678万 | 64 MiB | 16 MiB |

完整 Mip 链还会增加约三分之一。

所以不能简单规定“重要资产一律4K”，而要看：

- 摄像机最近距离；
- 屏幕占比；
- Texel Density；
- UV利用率；
- 是否可平铺；
- 是否能使用Detail Normal、Trim Sheet、Decal；
- 目标平台显存、包体和流送预算；
- AI生成、超分和人工修图成本。

此外还要定义拓扑、UV、材质槽、通道打包、色彩空间、LOD/Nanite、碰撞、骨骼、动画、VFX、Shader、Draw Call、命名和版权规范。

## 9. 重复性检测怎么做

必须区分：

1. 完全相同；
2. 裁剪、缩放、压缩后的近重复；
3. 主体、构图、姿态相似；
4. 风格/IP/版权风险。

推荐链路：

```text
SHA-256
→ 感知哈希
→ 图像 Embedding 向量召回
→ 局部特征和几何复核
→ 人工/法务判断
```

向量模型负责从大库中召回候选，FAISS 类索引负责高效相似度检索，但最终不能只依赖一个相似度分数。citeturn12search2turn12search6turn12search7

### 能不能不爬图，只搜三个网站

可以做成“**定向查询、临时比对、不建设全站镜像**”，前提是：

- 网站有官方API、站内搜索、以图搜图或商业授权；
- 能合法取得缩略图、图片内容或特征；
- 遵守服务条款、请求频率、缓存和删除要求；
- 不绕过登录、验证码、反爬或付费墙。

如果完全不读取图片或图片特征，只拿文字标题和URL，实际上无法完成视觉重复性对比。

## 10. 腾讯朱雀AI的原理

首先要纠正定位：

> 腾讯朱雀实验室公开的相关工具主要是AI生成内容鉴别，不是图片重复检测、以图搜图或版权侵权裁判。

腾讯公开页面能够确认其提供图片、文本等AI内容鉴别能力，但没有完整公开模型结构、训练集明细、特征权重和阈值策略。因此网上对其具体算法的描述不能直接视为腾讯内部实现。citeturn0search0turn0search1turn0search4turn0search6

比较合理的工程推测是：

- 使用真实内容和多种生成模型内容训练检测器；
- 综合语义、局部纹理、边缘、噪声和频域异常；
- 使用压缩、裁剪、截图、缩放等方式做增强；
- 组合多个检测器并进行置信度校准；
- 不断补充新生成模型样本，处理检测能力漂移。

但它只能成为一个风险信号：

```text
AI生成可能性
+ 内部生产血缘
+ 重复性检测
+ 授权与版权台账
+ 人工审核
= 最终准入决定
```

**AI生成不等于侵权，非AI也不等于没有侵权。**
