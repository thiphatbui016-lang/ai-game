## Photoshop 开放了哪些接口

### 1. 操作事件监听接口

Photoshop UXP 提供：

```javascript
action.addNotificationListener(events, callback)
```

插件可以订阅会改变文档的 Photoshop 事件，回调会返回：

```javascript
(eventName, actionDescriptor)
```

可监听的事件范围很广，包括：

- 打开、关闭文档
- 保存、另存、导出
- 创建、删除、选择图层
- 设置图层属性
- 移动、变换、裁剪
- 调色和滤镜
- 合并、复制、粘贴
- 画布尺寸、图像尺寸变化
- 通道、选区、蒙版等操作

Adobe 提供了正式的 Action Event Codes 列表。开发阶段可以使用 `all` 观察事件，但 `all` 只适合开发者模式；生产插件应形成经过测试的事件白名单。`action.addNotificationListener` 的最低 Photoshop 版本要求是 23.0。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/eventcodes?utm_source=openai))

示意代码：

```javascript
const { action } = require("photoshop");

const events = [
  "open",
  "save",
  "close",
  "make",
  "delete",
  "set",
  "select",
  "crop",
  "canvasSize"
];

await action.addNotificationListener(
  events,
  async (eventName, descriptor) => {
    await localQueue.append({
      eventId: crypto.randomUUID(),
      assetId,
      editSessionId,
      eventName,
      occurredAt: new Date().toISOString(),
      descriptor: normalizeDescriptor(descriptor)
    });
  }
);
```

### 2. 文档状态与 History 接口

插件可以读取当前文档的：

- `historyStates`
- `activeHistoryState`
- `layers`
- `activeLayers`
- `saved`
- `path`
- `width`、`height`
- `resolution`
- `mode`
- `colorProfileName`

也可以通过 `saveAs.psd`、`saveAs.psb`、`saveAs.png`、`saveAs.jpg` 等接口保存工作文件和预览图。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/document?utm_source=openai))

因此我们可以在关键节点生成 Checkpoint：

```json
  "active_seconds": 1360,

```

### 3. Photoshop 自带的 History Log

Photoshop 还开放了 History Preferences：

- `useHistoryLog`
- `editLogItems`
- `saveLogItems`
- `numberOfHistoryStates`
- `createFirstSnapshot`

History Log 可以保存到：

- 文件元数据
- 独立日志文件
- 两者同时保存

可保留的 History States 数量支持设置为 **1—1000**。这适合作为插件事件账本的补充证据，但不能代替我们的资产平台事件日志。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/preferences/preferenceshistory?utm_source=openai))

### 4. 把 AI 资产 ID 写入 PSD

Adobe 当前 UXP 还开放了 XMP 接口，可以把以下信息嵌入 PSD 文件：

```text
asset_id
asset_version_id
assignment_id
canvas_id
canvas_node_id
source_output_id
ai_run_id
handoff_id
edit_session_id
control_plane_url
```

`XMPFile` 可以读取、修改并安全写回 PSD 等支持 XMP 的文件。这意味着即使 PSD 被复制或脱离原文件夹，也可以重新识别它属于哪个 AI 任务和画布。([developer.adobe.com](https://developer.adobe.com/premiere-pro/uxp/uxp-api/reference-js/modules/uxp/xmp/xmp-classes/xmp-file?utm_source=openai))

建议同时保存三份身份信息：

1. PSD 内的 XMP Metadata；
2. 同目录的 `asset-manifest.json`；
3. 资产平台中的权威记录。

不能只依赖文件名。

## 为什么不能承诺 100% 全过程

### 限制一：部分 Modal 操作期间通知会被静默

Adobe 明确说明，当 Photoshop 处于非交互式 `executeAsModal` 状态时，事件通知会被静默，其他插件不能监听此期间执行的 `batchPlay` 命令。

这意味着：

- 某个第三方插件批量修改图像；
- Photoshop Action 执行一组命令；
- 某插件在 Modal Scope 中运行；

我们的插件可能只看到 Modal 开始和结束，而看不到其中每一个内部命令。Adobe提供了：

```text
modalJavaScriptScopeEnter
modalJavaScriptScopeExit
```

用于检测这类观察缺口。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal?utm_source=openai))

处理方式是：

```text
modalJavaScriptScopeEnter
→ 标记观测暂停
→ modalJavaScriptScopeExit
→ 立即生成完整 Checkpoint
→ 比较 History、Layer Tree 和 Preview Hash
```

### 限制二：History 不是永久审计账本

History State 的 ID 只在当前文档保持打开期间有效；历史数量也受 Photoshop 偏好上限影响。关闭、重新打开文档以后，不能把内存中的 History 对象当成永久生产记录。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/document?utm_source=openai))

所以不能只做：

```javascript
app.activeDocument.historyStates
```

必须把摘要持续写入资产平台。

### 限制三：没有开放每一个连续笔刷采样点

UXP 可以收到 Photoshop 操作通知，也可以通过 Checkpoint 比较文档状态，但没有一个官方接口能够保证输出：

```text
第 1 毫秒：笔刷位于 x=101, y=203
第 2 毫秒：像素 A 从 RGB 10,20,30 变成 11,22,33
……
```

这是根据 Adobe 当前提供的事件、History 和文档 API 能力边界作出的工程判断。要做到接近像素级重建，只能定期保存图像快照或版本，存储和性能成本会很高。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/eventcodes?utm_source=openai))

### 限制四：插件必须处于加载状态

Photoshop 的插件通常在面板被打开时加载；针对监听用户操作的插件，官方提供了启动时加载的配置方式。生产版本必须让监测插件随 Photoshop 启动，并在插件被卸载、关闭或异常退出时产生“观测中断”事件。([developer.adobe.com](https://developer.adobe.com/photoshop/uxp/2022/guides/uxp-guide/uxp-misc/manifest-v4/photoshop-manifest/?utm_source=openai))

## 针对你的产品，建议采用四层监测

### 第一层：操作事件

记录“做了什么”：

```text
document.opened
layer.created
layer.deleted
layer.renamed
layer.moved
selection.changed
transform.applied
filter.applied
adjustment.changed
document.saved
document.exported
document.closed
```

不建议直接永久保存所有原始 Action Descriptor。生产环境应先转换成统一语义：

```json
{
  "operation": "layer.transform",
  "target_layer_ids": [17],
  "parameters_summary": {
    "scale_x": 1.2,
    "scale_y": 1.2,
    "rotation": 5
  }
}
```

### 第二层：周期 Checkpoint

建议在这些时间生成状态快照：

- 打开资产时
- 每隔30—60秒
- Modal Scope 结束时
- 图层结构重大变化时
- 保存时
- 导出时
- 关闭文档前

Checkpoint 保存：

```text
History 数量与当前 History
Layer Tree 摘要
图层 ID、名称、类型、可见性
文档尺寸、色彩模式、色彩空间
当前文件保存状态
有效编辑时间
预览图 Hash
PSD 文件 Hash
```

### 第三层：版本资产

每次重要保存形成：

```text
Asset Version
├── master.psd / master.psb
├── preview.jpg
├── photoshop-edit-summary.json
├── source-ai-output.png
├── canvas-snapshot.json
├── ai-run-manifest.json
├── asset-manifest.json
└── sha256.json
```

这样即使中间某些事件没有被监听，也能通过版本和 Hash 证明最终资产发生了什么变化。

### 第四层：观测覆盖率

每个编辑会话都应展示：

```text
正常监听时间
插件离线时间
Photoshop Modal 时间
事件序列缺口
最后一次 Checkpoint
最后一次文件 Hash
综合观测覆盖率
```

因此产品表述应该是：

> “记录资产在 Photoshop 中的可观察生产过程，并对不可观察时段进行标记和版本补偿。”

而不是：

> “百分之百记录 Photoshop 中的全部底层操作。”

## 对当前 MVP 的判断

我们前面实现的 Photoshop UXP 骨架方向是正确的，已经包含：

- Handoff ID
- Edit Session
- 编辑事件
- Checkpoint
- 有效编辑时间
- History/Layer 摘要
- 离线事件序号
- 文件发布
- Asset Version

下一步需要把当前的模拟事件升级为：

1. 正式注册 `action.addNotificationListener`；
2. 增加插件随 Photoshop 启动加载；
3. 增加事件白名单及 Descriptor 语义转换；
4. 增加 Modal Enter/Exit 缺口检测；
5. 增加 PSD/PSB 真实保存、Hash 和分块上传；
6. 把 `asset_id`、`handoff_id` 写入 PSD 的 XMP；
7. 在资产平台展示编辑时间线、版本差异和观测覆盖率。

所以最终答案是：

> **有正式开放接口，能够实现企业生产意义上的全过程监测；但不能宣称像屏幕录像一样无遗漏地还原每个像素操作。正确方案是使用 UXP 事件监听、History Log、周期 Checkpoint、XMP 身份和资产版本 Hash 组合，形成可审计的 Photoshop 编辑过程。**
